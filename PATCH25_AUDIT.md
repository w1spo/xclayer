# XCLayer Patch 25 implementation audit

The supplied Patch 24 ZIP had SHA-256 `69759d2cbb835c4e2ad8136a233aacbc108e823b4f2de0d51e205f57825f2d16`. The local Git history starts with an import of that archive (`aba6b27`). The archive did not identify a corresponding upstream Git commit.

## Changelog

| Priority | Status | Changes and remaining limits |
| --- | --- | --- |
| BCPack | Implemented for six modes. Windows validation pending. | DirectStorage accepts BC1, BC3, BC4, BC5, BC6H and BC7 with the upstream exact entropy, reconstruction and dictionary tables. Both standalone BCPack and zlib followed by BCPack go through the existing ordered worker. Output is staged until decoding succeeds, then sent to the existing virtual or physical-page destination handling. The decoder returns BC blocks in stream order and enforces 16 MiB compressed and 8 MiB decoded limits per request. BC2 lacks a published lane layout. Requests with console hardware swizzle options still fail. Broader swizzle support needs verified numeric mode definitions and reference inputs and outputs. |
| Non-UMA coherence | Partially implemented. Hardware validation pending. | DirectStorage resolves fully reserved paired GPU spans to their CPU view and preserves direct mappings. Sparse GPU readbacks preserve dirty CPU edits in neighboring bytes of shared chunks. The title queue waits for GPU-only texture placements even with no CPU mirror. The complete multi-queue ownership and residency model, general texture UAV writeback and alias lifetime tracking remain open. |
| Mesh shader ABI | Partially implemented. Generated HLSL validated with DXC. | The pass-through uses the aligned D3D12 output budget and expands oversized records even when one group can hold their primitives. The dispatch multiplier and emitted groups come from the same partitioning rule. Amplification payloads, unverified primitive exports and general Wave64 execution on Wave32 hardware remain open. |
| D3D12.X operations | Partially implemented. Hardware validation pending. | Same-window non-overlapping copies use a bounded scratch buffer and legal D3D12 transitions. Recording-owned scratch references go through fence-based deferred release after reset, split-segment retirement or list release. Unknown slots, console PSO serialization and unsupported command payloads still require verified ABI or format evidence. |
| MADE and queue retirement | Not implemented. | Console code can copy descriptor data directly, keeping a reference to the original PC descriptor index without going through intercepted CopyDescriptors calls. A cache entry may still back one of those aliases, an active command recording or a GPU submission. Safe eviction requires tracking those relationships and backing generations across mapping changes. Existing MADE and retained-title-queue growth remain open. |
| CPU performance | Partially implemented. | Uncompressed virtual memory-to-memory DirectStorage requests with private destinations use one overlap-safe copy. Section-backed and UMA destinations keep their snapshot path because different virtual views may alias the same backing. GPU texture upload waits are still part of the existing ordering and resource-lifetime path. No title benchmark was available for the i5-6400. |
| Title memory accounting | Partially implemented. | Default XMem logical bytes are maintained incrementally across allocation, address reuse and successful frees. Existing logical allocation totals, system commit and video-memory totals are distinct. Complete coverage of custom allocation hooks, all mapped aliases and cache retention remains open. The existing TitleMemoryStatus policy stays in effect. |

## Validation

- The Patch 24 workspace passed a Windows GNU cross-target `cargo check --workspace --all-targets --locked --target x86_64-pc-windows-gnu`. The first MSVC cross-target attempt stopped in the C dependency build because the Linux environment had no `lib.exe` or Windows SDK.
- The Patch 25 workspace compiled and linked against the Windows GNU target in debug and optimized release. `cargo test --workspace --locked --no-run --target x86_64-pc-windows-gnu` built the Windows test executables.
- The isolated decoder ran 7 native tests with zero failures or ignores. It checked the symbols of the synthetic fixture set across all six modes and compared 8,192 decoded BC1 blocks byte-for-byte against an independent fixture expectation.
- The isolated sparse partial-readback regression ran one test, which passed. Two isolated default XMem ledger tests also passed. Linux DXC compiled all three generated mesh pass-through variants to `ms_6_6`. The variants covered within-budget, oversized single-group and oversized multi-group output. DXC rejected the Patch 24 equivalent of the one-primitive case because it exceeded the 32 KiB output limit.
- The final focused Windows GNU suite under Wine ran 33 tests. It had 32 passes, zero failures or ignored tests, and one internal GPU skip. This includes direct and zlib-wrapped BC1 queue requests, malformed-stream publication checks, paired addresses, mapped aliases, mesh sizing and sparse readback. The GPU-dependent test did not exercise the same-window copy.
- The broader workspace Wine run timed out after reporting nine graphics failures and a Wine page fault while running XAudio2 tests. All nine filtered graphics failures also reproduced on Patch 24. A separate Patch 24 XAudio2 run reproduced the read fault at address 0xDC. The optimized GNU executable printed its command help under Wine. Windows MSVC validation, dedicated-GPU runs, title smoke tests and target-hardware benchmarks are unavailable here. The Windows CI workflow accepts a manual dispatch on a hosted checkout.
